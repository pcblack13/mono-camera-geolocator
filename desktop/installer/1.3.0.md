# Mono Camera Geolocator 1.3.0

A feature release: the monitoring half of the product grows up. Fixed cameras
are watched by the app itself — detection, drift and data feeds come back after a
restart — and every geolocated detection now says whether the camera was still
trusted when it was placed. Recommended for everyone on 1.2.x.

## New

- **A globe of cameras, and a page per camera.** The Live stream tab became
  **Monitor**: a globe with one marker per registered camera, and a per-camera
  page with the video, a five-step inspector (source → detector → placement →
  tracking → drift) and map / detections / events decks. Each camera's setup is
  remembered; the map can pop out onto a second screen.
- **The camera list lives on the server.** Cameras are registered once and every
  machine sees the same list. A browser that ran 1.2.x is asked once whether to
  move its cameras across (their saved setups move with them).
- **Watches, runs and feeds survive a restart.** What you left running on a
  camera — a drift watch, a detection run, a data feed — is what the app is
  running again a few seconds after it starts. Pressing Stop is remembered too.
- **Every detection carries the camera's drift verdict.** A mark's coordinate is
  only valid while the camera has not moved since its lookup table was built;
  each mark (and each exported row) now records the drift monitor's confirmed
  verdict at the instant it was placed — `ok`, `moved`, `changed`, `degraded`,
  `pending`, or `unwatched` when nobody was checking. Marks placed under a
  confirmed move are still drawn, and the page says so.
- **Object detection on clips and live streams.** YOLO with an optional visual
  tracker handoff, marks placed through a lookup table, CSV / GeoJSON / Shapefile
  export, and every detection recorded durably in the database — from this
  machine's detector and from serial/HTTP data feeds alike.
- **Camera drift monitor.** Freeze a reference of what the camera sees, then check
  or watch it: a confirmed move or an optics change is reported with the rotation
  and metres named; a day-long soak report says whether the light fooled it.
- **Lookup-table import**, a **status page** with a live log, **Arabic** with a
  mirrored layout, a **display-size** control for large screens, a workflow guide,
  and a workchain of open pages that a relaunch restores.
- **Optional centre correction for marks.** Marks are read from an object's near
  edge; a per-camera option pushes them to the object's centre by half a typical
  vehicle length, and records the metres applied on every mark. Off by default.
- **Serial data feeds on Windows** (COM ports) as well as Linux.

## Fixed

- **Photographs with more than 50 control points** now show every marker on both
  panes, and a new point is never named after one that already exists.
- **Data-feed detections were not being recorded.** Marks arriving from a serial
  or HTTP feed now land in the same durable table as this machine's detections.
- The detection core's documentation described an algorithm the code no longer
  ran; it now lives with the app and says what it does.
- **The packaged app would not start** ("Cannot find module './zoom'"): the
  display-size module was never listed in the installer's file list. Builds made
  since the display-size control landed were affected.

## Enabling the object detector (YOLO)

Detection is locked until the runtime and a weights file are on the machine —
see `INSTALL.md`, "Enabling the object detector".

## Note for existing installations

The database is upgraded on first launch (a `cameras` table and provenance
columns on `detection_events`). Your projects, images, points and lookup tables
are kept. The provider list is still read from the running copy's configuration
(`~/.local/share/MonoCameraGeolocator/work/.env` on Linux) — diff it against
`backend/.env` after upgrading, as `RELEASE_CHECKLIST.md` §3 says.

## Install

Windows: run `MonoCameraGeolocator-Setup-1.3.0.exe` (first launch ~1 min).

Linux (Ubuntu/Debian):

```bash
sudo apt install ./mono-camera-geolocator_1.3.0_amd64.deb
```

Your projects and data are kept across upgrades.
